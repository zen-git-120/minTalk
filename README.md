# minTalk

少人数のミーティングや勉強会で次に話す人をランダムに選ぶWebアプリです。全員に発言の順番が回るようにします。

Reactの学習を兼ねて開発しています。現在は開発環境の構築とGitHub連携まで完了しており、以下のアプリ機能は実装予定です。

## 1. サービスとしての目的

- **対象ユーザー（想定）：** 少人数のミーティングや勉強会の進行役。
- **困る場面（仮説）：** 次に誰が話すか迷ったり、誰がまだ話していないか分からなくなったりする。
- **目指す結果：** 未発言のメンバーから次の話者を選び、全員が一度ずつ話せる。
- **最初の利用者：** 開発者本人とプログラミングスクール受講生。

## 2. 今回学ぶこと

- **中心テーマ：** Reactの状態管理と状態に応じた画面表示。
- **使う場所：** メンバーの追加、話者の選択、発言済みへの変更、リセット。
- **説明できるようになりたいこと：** 操作によってどのデータが変わり、なぜ画面が変わるのか。
- **周辺技術：** JavaScript・HTML・CSSを必要な範囲で学び、Viteで開発する。Git・GitHubで変更を記録する。
- **今回扱わない学習テーマ：** サーバー開発、データベース、ログイン認証。

## 3. 操作と処理の流れ

| 操作 | 処理 | 状態の変化 | 表示 |
|---|---|---|---|
| 名前を入力して追加 | 前後の空白を取り除き、空白・重複を確認する | 未発言のメンバーを追加する | 一覧に名前を表示する |
| ランダムに選ぶ | 未発言のメンバーから1人を抽選する | 現在の話者を設定する | 選ばれた名前を表示する |
| 話し終えた | 現在の話者を発言済みにする | 発言状況を更新し、現在の話者を空にする | 話者表示と一覧を更新する |
| 最初から | 発言状況を初期化する | メンバーを残し、全員を未発言にする | 次の抽選ができる画面に戻す |

状態と画面の対応が分からなくなったら操作の前後で「メンバー・現在の話者・発言状況」がどう変わるかを書き出して確認します。

## 4. 最初に作る機能

| 機能 | 必要な理由 | 学習との関係 |
|---|---|---|
| 名前入力・メンバー追加 | 抽選する参加者を登録する | 入力値と配列の状態管理 |
| メンバー一覧 | 参加者と発言状況を確認する | 配列から画面を表示する |
| ランダムな話者選択 | 次の話者を決める | 抽選対象の絞り込みと状態更新 |
| 発言完了 | 同じ回での再選出を防ぐ | メンバーの状態更新 |
| リセット | 同じメンバーでもう一巡する | 複数の状態の初期化 |

### 決定した動作ルール

- 話し終えたメンバーはリセットするまで抽選対象から外す。
- 「ランダムに選ぶ」で未発言のメンバーから1人を選ぶ。
- 現在の話者がいる間は「ランダムに選ぶ」を押せない。
- 「話し終えた」で現在の話者を発言済みにし話者表示を空にする。次の人は自動で選ばない。
- 全員が話し終えたら「全員が話し終わりました」と表示する。
- 「最初から」でメンバーを残して現在の話者と発言済みの記録をリセットする。
- 名前の前後の空白は取り除く。空白だけの名前と登録済みの同じ名前は追加できない。
- 途中で追加したメンバーはその回の未発言メンバーとして抽選に参加できる。

### 今回作らない機能

ログイン、複数端末での共有、発言時間の計測、履歴保存、メンバーの個別編集・削除は最初の版には含めません。

## 5. 人に使ってもらう準備

- **データ：** 名前・現在の話者・発言状況を開いている画面内だけで保持する。外部サーバーへの保存は行わない。
- **保存期間・削除：** 再読み込みや画面を閉じる操作でデータを消す。「最初から」は名前を消さない。
- **ログイン・アクセス権：** ログインは設けず、その画面を操作する人が登録・抽選・リセットを行う。別端末とは共有しない。
- **入力ミス：** 空白や重複は追加せず、理由を画面に表示する。
- **操作できない場合：** メンバーがいない場合や抽選対象がいない場合のボタン・案内を実装時に整理する。
- **公開先：** GitHub Pagesを予定。公開URLは公開後に記載する。
- **公開範囲：** アプリとソースコードを一般公開する予定。コードや説明用画像には実在する参加者の情報を含めない。
- **費用：** 有料サービスは使わない方針。公開時に利用条件を確認する。
- **不具合の連絡：** GitHub Issuesを窓口にする案。個人情報を含めないよう案内する。

## 6. 完了の確認

### サービスとしての確認

- 0人・1人・複数人の状態で表示と操作を確認する。
- 複数人を追加し同じ人が再選出されずに全員の発言が終了する。
- 途中追加とリセットが決定したルールどおりに動く。
- スマホ幅でも名前の入力と各ボタンの操作ができる。
- 実際の進行役に試してもらい「次の人を決めやすいか」「未発言の人を把握しやすいか」を確認する。

### 技術・学習としての確認

- 各操作の前後で状態と表示がどう変わったか確認する。
- 「話し終えた」から次の抽選までの処理を自分の言葉で説明する。
- 小さな表示変更について結果を予測し実際の結果と比べる。
- 公開用のビルドが成功し公開URLでも一連の操作ができることを確認する。

## 7. 開発・実行方法

### 使用技術

React / JavaScript / CSS / Vite / Oxlint

開発時のNode.jsは `v24.16.0`。

### セットアップ

リポジトリを取得した後、プロジェクトのフォルダーで実行します。

```sh
npm install
```

### 開発用サーバーの起動

```sh
npm run dev
```

ターミナルに表示されたLocalのURLをブラウザーで開きます。今回の環境では `http://localhost:5173/` で初期画面を確認しました。

### その他の確認

ビルド・リンターの実行コマンドは既存の `package.json` を確認後に追記します。環境変数は現在設定していません。
